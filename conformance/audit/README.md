# roe-guard audit v2 conformance vectors

Language-neutral verification vectors for the roe-guard audit record v2
(SPEC §14.7). Any implementation of the audit format MUST reach the same
verdict on every case.

## Layout

```
conformance/audit/cases.json   chain-verification cases
conformance/jcs/cases.json     JCS (RFC 8785 subset) canonicalization cases
```

Files are generated by `conformance/tools/gen_audit_vectors.py`; verify
with `python conformance/tools/gen_audit_vectors.py --check`.

## Chain case format

`{"format": 1, "suite": "audit-v2", "cases": [...]}`. Each case carries:

- `chain`: the audit file contents as line strings (no trailing `\n`).
  A consumer writes each element followed by a newline.
- `checkpoints`: checkpoint lines, or `null`.
- `public_keys`: `{"sha256:<hex>": "<hex public key>"}` or `null`.
- `expected`: `{"valid": bool, "broken_at_index": int | null,
  "reason_code": str | null}`.

`broken_at_index` is the failing line index; for `CHAIN_TRUNCATED` it is
the number of records present; checkpoint failures carry the checkpoint
`seq`; `CHECKPOINT_MISSING` carries `null`.

## Signing key

The checkpoints are signed with the RFC 8032 §7.1 TEST 1 key. It is a
published test vector, not a secret; never use it in production.

## JCS cases

Each case has `input_json` and either `expected_hex` (the canonical
UTF-8 bytes in hex) or `expected_error` (`UNSUPPORTED_NUMBER`,
`LONE_SURROGATE`, ...). The ordering case is the RFC 8785 §3.2.3
example: keys sort by their UTF-16 code units, so the emoji (U+1F600)
precedes U+FB33.

## Verification order

SPEC §14.7 fixes the failure-code order per line: `INVALID_JSON` →
`MALFORMED` → `UNKNOWN_VERSION` → `UNKNOWN_FIELD` → `TIMESTAMP_FORMAT`
→ `CHAIN_ID_MISMATCH` → `SEQ_MISMATCH` → `PREV_HASH_MISMATCH` →
`ENTRY_HASH_MISMATCH`, with `VERSION_DOWNGRADE` when a v1 line follows
a v2 line, and the checkpoint order `CHECKPOINT_MISSING` →
`CHECKPOINT_MALFORMED` → `CHAIN_ID_MISMATCH` → `CHECKPOINT_KEY_UNKNOWN`
→ `SIGNING_BACKEND_UNAVAILABLE` → `CHECKPOINT_SIGNATURE_INVALID` →
`CHAIN_TRUNCATED` → `CHECKPOINT_HEAD_MISMATCH`. Tail truncation without
a checkpoint is a known undetectable boundary.
